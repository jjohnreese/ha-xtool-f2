Fixes the regular F2 Status sensor staying at `processing` while a job is
paused. The WS-V2 protocol now decodes the pause state from all three
sources the F2 uses:

- Status string `P_PAUSE` maps to `paused`.
- A `WORK_PAUSED` push event (info `working`) sets the status to `paused`.
- Runtime polling in `WORK` mode uses `subMode` to distinguish
  `workReady` (processing ready), `working` (processing) and
  `workPause` (paused).

Adds a README automation example for controlling jobs with a ZHA wireless
button: single press pauses/resumes/starts based on the reported status,
double press repeats the last job. The example relies on this pause-state
fix; confirm the Status sensor reports `paused` before using it.

Validation: 19 F2 repeat regression tests pass and the protocol module
compiles. The pause-state mapping has no dedicated automated test.

This candidate is being installed through HACS from jjohnreese/ha-xtool-f2.
Scope: regular F2 GS006, firmware 40.56.024.00.ht3; Home Assistant
2026.10.4. Other models/firmware are outside the verified scope.
